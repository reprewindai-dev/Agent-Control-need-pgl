ANTI-GAMING CONTROLS (HARDCODED)
================================================================================

Control 1: Randomized Timing
  Base: 3,600s | Jitter: ±900s (±15 min)
  Code: Math.random() * 1800000 - 900000 (locked in agent.js)
  Result: No predictable schedule

Control 2: Rotating Node Identities
  IP rotation: Every 10 requests
  User-Agent: Randomized per request (50-agent pool)
  TLS cipher: Randomized per request
  Code: Hardcoded in vnp_measurement_agent.js
  Result: Indistinguishable from real traffic

Control 3: Traffic Replay (eBPF)
  Payloads from real-world traces
  Concurrency: Randomized 5–20 requests
  Think time: Exponential distribution
  Code: Hardcoded in agent
  Result: Realistic traffic patterns

Control 4: Outlier Detection (Automatic)
  Threshold: 3σ from peer group
  Service: Python, runs hourly
  Action: Flag + auto re-run
  Code: Hardcoded in scorer.py
  Result: Detects corruption automatically

Control 5: Spot Checks (Audit)
  Frequency: 5% of measurements
  Process: Independent node re-runs test
  Tolerance: ±10% match
  Code: In public API (GET /v1/spot-checks)
  Result: Incentivizes honesty

WHAT HAPPENS IF SOMETHING BREAKS
================================================================================

Measurement Node Down (1 of 5)?
  → Redundancy: 4 remaining nodes still collect data
  → Score quality: ±5 points confidence interval (acceptable)
  → Action: Auto-restart via docker-compose health checks

ClickHouse Fails?
  → Replication: Data on other 2 nodes
  → Recovery: <5 min failover
  → Data loss: Zero (all measurements anchored on-chain hourly)

Scoring Engine Crashes?
  → Queue: Kafka accumulates measurements
  → Recovery: Catch-up scoring on restart (backfill all hourly batches)
  → Score latency: Max 24 hours behind (within acceptable range)

Base L2 Network Issue?
  → Fallback: Batch anchors every 24 hours instead of hourly
  → Data safety: All measurements stored locally, safe
  → Recovery: Resume hourly anchoring when network recovers

Dashboard Down?
  → Fallback: REST API still works (scores queryable)
  → Recovery: Vercel auto-redeploy from GitHub
  → Impact: Visual only; data access unaffected

Public API Rate Limited?
  → Expected: 1,000 req/hour per IP is standard
  → Workaround: Cache results locally, batch queries
  → Impact: None (agents implement caching naturally)
